# Проект MD2DOC Format 0.1/0.2

Проект — папка с `document.yaml`, Markdown и ресурсами. Манифест содержит
ссылки `styles` и `metadata` на два файла конфигурации внутри этой папки;
имена и вложенные каталоги произвольны. Все три `schema_version` должны совпадать.
JSON-синтаксис допустим как подмножество YAML. Рабочий искусственный пример:
[`examples/minimal`](../examples/minimal).

`document.yaml` задаёт `id`, `language`, `build`, `defaults` и упорядоченный
массив `elements`. Элементы содержат уникальный `id`, `type`, относительный
`source`, а при необходимости `children`, `enabled`, `heading`, `style`,
`numbering` и `page_break`. Заголовок берётся из первого Markdown-heading
при `heading.from: markdown` или из `heading.text` при `from: yaml`.
Порядок документа определяется манифестом, не сортировкой файлов.

`metadata.yaml` хранит название, автора, организацию, дату и другие метаданные.
`styles.yaml` задаёт страницу, шрифты, абзацы, H1–H6, списки, таблицы,
изображения, именованные стили, разрывы и колонтитулы. Размерности принимают
единицы `mm`, `cm`, `pt`, `in`; точные допустимые поля/диапазоны определяет
[`src/md2doc/config/validation.py`](../src/md2doc/config/validation.py).
Правила наследования и нумерации:
[`config/heading_numbering.py`](../src/md2doc/config/heading_numbering.py)
и [NUMBERING.md](NUMBERING.md). Это схемы внутри Python-пакета; отдельный
исторический валидатор или прототип не нужен.

В **0.1** структурная нумерация остаётся текстовой. В **0.2** поддерживаются
нативные многоуровневые списки Word для структуры и Markdown H1–H6,
настройки уровней `heading_numbering` и локальные директивы. Не переносите
поля схемы 0.2 в 0.1 без проверки. Базовые фикстуры 0.1 сохранены в
[`tests/fixtures`](../tests/fixtures), пример 0.2 — в `examples/minimal`.

Пути должны оставаться внутри проекта; ссылки, исполняемые YAML-теги,
дублированные ключи и активные/внешние SVG-ресурсы отклоняются. Проект не
может подставить исполняемый Python-валидатор. Studio сохраняет комментарии,
BOM, окончания строк и пользовательские расширения; перед записью проверяет
внешние изменения и создаёт резервную копию вне проекта.

Для первого запуска скопируйте `examples/minimal` в свою папку, откройте её
в Studio и нажмите «Конвертировать в DOCX». Каталог `output` уже существует.
Ни пример, ни автоматические тесты не требуют личных рабочих документов.
