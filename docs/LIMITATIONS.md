# Ограничения текущей версии

- Studio работает локально через localhost для одного пользователя; облака,
  совместного редактирования, БД проектов и постоянной истории сборок нет.
- Открываются существующие проекты. Для нового используйте копию
  `examples/minimal`; полноценный мастер создания не реализован.
- Предпросмотр Markdown/оформления приблизительный и не заменяет Word.
  H1–H6, структурные заголовки и обычные списки имеют разные правила;
  их описывает [NUMBERING](NUMBERING.md).
- Нумерация Word задаётся напрямую в абзацах. Назначение одного Heading-стиля
  новому абзацу в Word не добавляет его в список: продолжите список средствами
  Word либо пересоберите Markdown. Девять уровней OOXML не расширяют Markdown
  сверх H1–H6. Исправление 0.2.3 и пределы проверки: [WORD_READBACK_FIX](WORD_READBACK_FIX.md).
- Неподдерживаемый Markdown останавливается валидатором. Сетевые ресурсы,
  активные SVG, внешние SVG-зависимости и исполняемые YAML-теги запрещены.
  SVG требует [системной Cairo](CAIRO_WINDOWS.md), PNG/JPEG — нет.
- Визуальные настройки покрывают часть схемы; остальные поддерживаемые поля
  доступны в YAML. Расширения/комментарии сохраняются, внешние изменения
  вызывают конфликт. Перед записью делается резервная копия.
- Открытие DOCX требует системной ассоциации/Word; Проводник и диалог папки
  используют Windows shell. Передача команды ОС не гарантирует визуальный
  результат стороннего приложения. Автотесты не запускают Microsoft Word.
- Имена результатов определяет `build` в manifest или явный `--output`.
  Конвертация не переименовывает пользовательские проекты по шаблону.
- Схемы 0.1 и 0.2 поставляются внутри Python Core; исторический внешний
  валидатор и UI-прототипы не нужны. Входной проект не исполняет Python.
