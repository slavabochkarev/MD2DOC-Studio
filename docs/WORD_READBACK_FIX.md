# Нумерация Word в Core 0.2.3

В рабочем прямом профиле определения списка задаются в numbering.xml, а
абзацы получают numId/ilvl через numPr. Heading-стили сохраняются отдельно.
Для обычного сброса по родительскому уровню lvlRestart не создаётся; для
продолжения записывается lvlRestart=0. Генератор/схемы при публикации не менялись.

Изменение 0.2.3 устранило наблюдаемую потерю вложенных номеров при открытии
одного из пользовательских документов в Word: после сохранения прежних
пакетов Word заменял numFmt вложенных уровней на none и очищал lvlText.
Результат новой версии вручную подтверждён владельцем 11.11.2026. Частные
документы и их копии не включены в репозиторий.

Нельзя заключать из одного примера, что все положительные lvlRestart сами
по себе недопустимы. [MS-OI29500 2.1.282](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/140a2cd9-2f26-456d-9760-ae6ecef4e8b5)
описывает поддерживаемые Word значения и сброс при отсутствии элемента.
Автоматические проверки XML/SDK не заменяют визуальную проверку всех версий Word.

Регрессии: `tests/test_word_numbering.py`, `tests/test_heading_numbering.py`,
`src/md2doc/diagnostics/numbering_graph.py`. Проверяются диапазоны, связи,
H1–H6, continue, шаблоны, скрытые уровни и независимость обычных списков.
Для ручного испытания создайте искусственный DOCX через
`tools/verify_delivery/create_diagnostic.py`. Word автоматически не запускается.
