# Состав рабочего репозитория

Публикуется одна реализация: `studio/frontend/src` + `studio/backend/md2doc_web`,
поверх независимого Core `src/md2doc`. CLI, пакетные схемы, тесты ядра и Studio,
фикстуры, инструменты проверки, lock-файлы и искусственный `examples/minimal`
нужны для воспроизводимой разработки и сохранены независимо от даты создания.

`design/ui` проверен отдельно: ранние HTML-прототипы, MVP, v2, альтернативы,
архивы и research не импортируются рабочим приложением. Документы там описывают
этап до реализации и не нужны для запуска/сопровождения текущего кода. Весь
каталог исключён через `.gitignore`; локальные файлы сохраняются. Актуальные
контракты описаны в `docs/FORMAT.md`, `docs/ARCHITECTURE.md`, `studio/README.md`,
`studio/HEADER_SUPPORT.md` и в схемах Python/полях frontend.

Локальные отчёты прежних этапов с устаревшими инструкциями и личными путями
исключены поимённо. Текущие документы ядра и исправления нумерации сохранены.
Кеши, QA, сборки, venv, node_modules, секреты и личные проекты в Git не входят.
Frontend build воспроизводится через Setup или команды из README.

Весь каталог `output` не исключается: искусственный пример сохраняет
`output/.gitkeep`, а тестовые эталоны в `tests/fixtures` можно хранить отдельно.
Генерируемые DOCX и build-report в output игнорируются; каждый новый бинарный
эталон следует отдельно проверять на назначение и конфиденциальные данные.

Перед публикацией проверяйте `git diff --cached`, `git ls-files` и отсутствие
секретов/случайных больших файлов. Для уже отслеживаемого локального прототипа
используйте только `git rm --cached` с конкретным путём и сохраняйте исключение;
обычный `git rm` удаляет рабочий файл. Историю и теги не переписывайте.

Исходная удалённая история с MIT LICENSE сохранена как предок выпуска.
Чистая копия должна собираться и открывать искусственный пример без
`design/ui`, личных каталогов и исходного пути разработки.
