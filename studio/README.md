# MD2DOC Studio — локальная рабочая версия

SvelteKit + FastAPI + существующий MD2DOC Core 0.2.3. Приложение открывает существующие проекты формата 0.1/0.2 и работает на Windows 11 через localhost.

Инструкция по применению изменений приложения: **[пересборка frontend и перезапуск backend](UPDATE.md)**. В ней есть команды через `npx.cmd` и остановка сервера, работающего в фоне.

## Установка и запуск

Первый запуск из чистого клона описан в [корневом README](../README.md).
Из корня проекта выполните `studio/Setup-Studio.ps1`, затем `studio/Start-Studio.ps1`.
Нужны Python 3.12+ и Node.js 22.12+ с npm/npx для первой сборки.
Python-зависимости фиксирует `studio/requirements.lock`, frontend — `frontend/pnpm-lock.yaml`.
Setup использует pnpm 11.25.0 напрямую либо через npx; собранный frontend в Git не включён.

Интерфейс: http://127.0.0.1:8731. Остановка — Ctrl+C. Другой порт:
`Start-Studio.ps1 -Port 8732`, без браузера — `-NoBrowser`.
Повторный запуск распознаёт работающую Studio; чужой процесс не останавливается.
Для SVG отдельно настройте [Cairo](../docs/CAIRO_WINDOWS.md).

## Получить документ

1. Нажмите **Открыть проект**, затем **Выбрать папку…** рядом с полем пути. Откроется системный диалог Windows для выбора папки с `document.yaml`; путь можно также ввести вручную. Файлы стилей и метаданных читаются по ссылкам из манифеста, включая нестандартные имена и вложенные каталоги.
2. Вкладка **Редактор** показывает структуру итогового документа по умолчанию. Переключатель **Файлы** показывает каталог проекта. В центре работает CodeMirror 6: редактируйте Markdown, сохраняйте кнопкой **Сохранить** или **Ctrl+S**, отменяйте черновик кнопкой **Отменить**. HTML-просмотр обновляется при вводе и не записывает черновик на диск.
3. Во вкладке **Настройки** выберите категорию и измените нужные поля. Для заголовков и нумерации переключайте H1–H6. Номера в примере справа рассчитывает существующее ядро по реальным заголовкам проекта. Образец шрифтов и страницы приблизительный.
4. Нажмите **Сохранить настройки**. Для ручного изменения конфигурации выберите **Редактор YAML**, затем нужный файл. Его имя берётся из фактических ссылок манифеста. Кнопка **Проверить YAML** проверяет синтаксис и схему, **Сохранить YAML** / **Ctrl+S** проверяет и записывает текст. Изменения путей `styles` и `metadata` в `document.yaml` после сохранения переключают Studio на новые существующие файлы внутри проекта. Комментарии и расширения не удаляются автоматически. Перед сменой режима с черновиком появится выбор сохранения либо отмены.
5. Большая синяя кнопка формирует **весь документ**, а не выбранный Markdown-файл. Путь результата берётся из `document.yaml`; кнопка с шестерёнкой рядом с конвертацией позволяет указать другой полный путь к `.docx` и включить строгий режим. Переопределённый путь не записывается в манифест.
6. Внизу видны этап, результат, предупреждения и ошибки. **Открыть DOCX** передаёт файл приложению по умолчанию в Windows. **Открыть папку** запускает `explorer.exe` с запросом нового окна и выделением DOCX. Статус подтверждает передачу команды Windows; отказ запуска отображается в диагностике. После команды появляется уведомление, при отказе — сообщение с кодом Windows и диагностикой. **Скачать DOCX** работает независимо от наличия Word. Во время конвертации приложения ОС автоматически не запускаются.

Визуальные параметры верхнего колонтитула находятся в категории **Колонтитулы**, в отдельной группе **Верхний колонтитул**. Обычная и первая страница настраиваются отдельно. Поддерживаемые параметры и ограничения описаны в [HEADER_SUPPORT.md](HEADER_SUPPORT.md).

Индикаторы Markdown, YAML и визуального оформления независимы. При смене файла/проекта или конвертации Studio предложит сохранить соответствующие черновики либо явно отказаться от них. Переключение основных вкладок сохраняет черновики в памяти.

При обновлении страницы браузера открытый проект и текущая сборка восстанавливаются из памяти работающего сервера. Несохранённый черновик браузер предупреждает потерять при закрытии; постоянного хранения черновиков нет. После перезапуска сервера проект открывается заново.

## Сохранение и конвертация

- В визуальном режиме изменяются только выбранные поддерживаемые параметры YAML. Остальные значения, расширения `x-*`, порядок элементов и массивы сохраняются. Возможны изменения форматирования YAML; BOM и CRLF сохраняются. Комментарии дополнительно проверяются лексером: если визуальная операция могла бы удалить комментарий, запись останавливается с объяснением. В редакторе YAML сохраняется именно введённый пользователем текст, включая комментарии и расширения. Неподдерживаемое схемой поле вызывает ошибку проверки, а не автоматическое удаление.
- Перед записью YAML используется существующая централизованная проверка проекта. Studio не меняет версию схемы и не выполняет автоматическую миграцию. Нативная нумерация H1–H6 доступна для 0.2; в 0.1 сохраняются существующие правила структурной нумерации. Markdown записывается только по явному сохранению; незавершённый документ можно сохранить и затем исправить ошибки проекта перед сборкой.
- Хэши конфигураций и выбранного Markdown защищают от перезаписи внешних изменений. При конфликте черновик остаётся в редакторе. Скопируйте нужные изменения перед перечитыванием: **Перечитать Markdown** перечитывает файл, **Перечитать проект** в верхней панели обновляет конфигурации. Несохранённые данные можно сбросить только явно.
- Перед сохранением создаётся резервная копия и журнал транзакции в `%LOCALAPPDATA%\MD2DOCStudio`. Каждый файл заменяется атомарно. При прерванной записи журнал используется для отката при следующем открытии проекта. Если файлы после прерывания были изменены вручную, автоматический откат останавливается с указанием резервной копии.
- Сборка идёт на временном снимке проекта. Последовательно запускаются `tools/verify_delivery --input-only`, `python -m md2doc build` и `tools/verify_delivery --output`. Итоговый DOCX заменяется только после успешной проверки. Отмена, ошибка или изменение исходников во время сборки сохраняют предыдущий результат.
- Временные файлы и резервные копии хранятся вне проекта. Путь можно переопределить переменной `MD2DOC_STUDIO_DATA`; он должен находиться вне открываемого проекта.
- Приложение слушает только `127.0.0.1`, без облака, базы данных и авторизации. Рассчитано на один открытый проект и одну текущую сборку. Не публикуйте этот сервер в сеть.

## Разработка

```powershell
.\studio\.venv\Scripts\python.exe -m pytest studio/tests -q
cd studio/frontend
pnpm check
pnpm build
```

После изменения backend перезапустите сервер. После сборки frontend обновите страницу браузера. Для frontend с Vite можно использовать `pnpm dev`; `/api` проксируется на backend с портом 8731.

Основные backend-проверки используют искусственный `examples/minimal` и временные копии. Внешние эталоны подключаются необязательными переменными из корневого README; личные проекты не требуются и не изменяются.
